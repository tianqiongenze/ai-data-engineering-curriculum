② 情境引入：首轮没达线，怎么办

你所在的小组承接 Q1 冻结的数据集 v1，按训练工单在 2×GPU 上跑训练与评测， 验收线由产品方按"漏检率"给定。首轮评测未达线，测试集本身可信度存疑（部分样本标签来自外包批次）。

组长只说了一句："诊断段由你本人主责、算法负责人评审方案——归因要讲证据，不许拍脑袋。"

你的任务（两段都要跑完）

执行段（13h）：核对数据集版本／超参／算力三项并启动训练；监控显存／损失曲线，异常即停上报；测试集跑评测出指标表；归档实验记录。

诊断段（17h）：抽检 200 条反推主因；按数据／超参／代码／算力四类分层归因并排优先级；设计 ≤3 组调优组合做 A/B 对照复测；留回退记录。

硬约束（违反任何一条，后果见"红线"）

  • 超参变更须指导人签认
  • 单次训练 ≤4h（算力配额）
  • 诊断段由本人主责、算法负责人评审方案
  • 异常回退上一版本
  • 验收线由产品方按"漏检率"给定，不得自行下调
  • 本情境含执行段与诊断段两段，六步全程贯通

已知条件：Q1 冻结数据集 v1 与数据卡、训练工单、配置模板、评测规范、算力配额单（2×GPU）、归因清单、TensorBoard。本模块所有数据均为教学样例，不含任何真实客户数据与个人信息。

⑤ 仿真实训：训练监控仪表盘模拟器

这里是 GPU 工位的模拟。核心决策点：首轮不达标时怎么归因。你会依次经历：执行确认 → 训练监控（看曲线与告警）→ 评测出指标 → 四类归因决策 → A/B 验证设计 → 回退与归档 → 复盘。选错归因，系统给你完整的后果链——归因错→调错方向→浪费算力。

红线警示（课标⑥.3 Q2 D 类硬约束原文——仿真里各对应一个会"炸号"的按钮，别手痒）：
  1. ① 未签认即改超参 → 本次实验作废 + 重做【A/B 区"不签认直接改 lr"】
  2. ② 隐去失败实验只报达标结果 → 一票否决【归档区"只归档达标结果"】
  3. ③ 把客户数据或模型权重上传公网／外部 API → 本课 0 分 + 上报【归档区"传外部 API"】
  4. ④ 测试集参与训练（含"看一眼再调"）→ 本次结果作废【A/B 区"把测试集加进训练集"】
  5. ⑤ 未留回退记录即覆盖上一版本 → 重做【归档区"不留回退记录直接覆盖"】
  6. 作业纪律：异常即停上报，不绕告警续跑【监控区"忽略告警继续跑"】（课标④.2 G4：显存与损失异常 3 分钟内停机上报）
